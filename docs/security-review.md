# 本次实现的交付自查

## 0.3.1 增量

新增 Windows 原生托盘仅处理显示/退出两个固定操作；原生消息线程不访问 Tk，操作在主线程处理，重复通知合并有界。隐藏窗口不修改信任或停止共享，退出等待正在进行的启停操作完成后收尾。图标初始化失败时保留普通窗口行为，Explorer 重启后尝试恢复图标。

精简移除重复 Tcl/Tk 和未使用的上游 GUI/翻译/图片/SVG/样式插件，保留核心所需 Qt、平台、网络及 TLS 库、许可证与对应源码。普通核心及保留库逐项与原文件核对摘要；PE 导入依赖检查未发现引用已移除的附带 DLL。没有合并 Python 与核心的 DLL 搜索路径，没有移除加密或双方指纹校验。服务专用核心和编入服务的清单按精简后的库存重新生成，原有固定摘要与权限约束保留。

Windows 安装器默认当前用户权限，不新增网络/登录接口，不自动启动共享或安装服务，不修改防火墙、自启动或系统登录策略；配置目录独立于安装文件，卸载保留本机身份。GitHub 仅手动构建，构建 job 内容只读、不保存 checkout 凭据；只有创建草稿的 job 有内容写权限。Actions 固定提交，上游二进制固定 SHA-256。源码/安装包排除运行配置、私钥和日志。下载源来自固定可信配置，限制大小/时间，ZIP 解压检查目录、链接、文件数和总量。

已验证：33 项单元回归，Windows 原生托盘创建/隐藏/恢复/故障回退/退出等待，冻结 GUI 启动，实际冻结程序生成并保留身份及核心版本加载，精简后的 C# 快照与清单校验，当前用户安装/卸载。服务测试曾在受限沙箱中清理临时 DLL 失败，改在正常权限环境重跑完整流程通过；没有将失败结果当作通过。

**跨平台交付补充**：Mac ARM / Intel 和 Ubuntu 26.04 已在原生 CI 完成构建、安装副本、身份/核心加载与图形进程启动检查。Intel 缺少 wheel 的依赖保持原版本，使用官方 PyPI 固定 SHA-256 源包及锁定构建工具，cryptography 静态链接 OpenSSL。DMG 只读挂载原始已验摘要的上游镜像；许可证保留并在构建挂载时提供明确同意响应。公开源码与发行附件仍排除私钥/运行配置；CI 日志不输出私钥或键鼠内容。CLI 输出统一 UTF-8，修复英文 Windows 诊断失败，没有改变认证、配对或网络授权。

**仍需人工安全评审 / 实机验收**：此前标记的普通核心 IPC、SYSTEM 锁屏服务和身份名称绑定边界保持不变。本次没有干扰正在运行的旧版共享，未复测实际键鼠事件与锁屏输入。Mac Developer ID 签名/公证、系统输入权限、Wayland portal、实体输入与跨机行为仍需验收；CI 安装和进程检查不替代这些结果。

## 0.3.0 增量

Mac 单设备默认共享端选择只使用已配对记录，不从网络自动授信；多设备保留明确选择。Windows 接收锁屏新增 SYSTEM 服务边界，安装器核对 Windows 控制台用户及 NTFS 快照所有者，不能只信任 JSON 自称的 owner_sid。服务由 SCM 系统鉴权控制；配置、身份及程序装入仅 SYSTEM/Administrators 可写的固定目录，所有机器码文件校验清单，清单摘要编入服务。只运行固定 client 核心与固定设置文件，没有任意路径/命令控制接口。后台每次启动都核对快照用户与控制台会话，启动前和恢复线程前再次核对；子核心置于 kill-on-close Job Object。

服务专用核心在 listen 之前把 WorldAccessOption 改为 UserAccessOption，避免依赖管道创建后再改权限。原二进制 SHA-256、指令字节、文件偏移受固定前置条件约束，仅修改一个字节；保留对应源代码补丁及 REA 指令证据。普通桌面核心没有该修改。TLS、证书 pin 与进入/离开屏幕的命令禁用保持强制；服务配置关闭剪贴板，身份不写到发行包或日志。

33 项单元回归、C# 编译、实际编译产物的快照/注入/端口/引擎完整性校验已通过。当前旧版核心仍在用户共享，原生 IPC 受限令牌回归被跳过；没有绕过原生单实例保护，也没有停止用户共享来伪造通过结论。

**需人工安全评审**：SYSTEM token/控制台会话切换、原生输入与解析路径、服务专用核心修改和发布许可材料；SYSTEM 下 IPC ACL 与真实锁屏/解锁、用户切换尚未运行验收。管理员部署和实机验收是后续必要步骤，0.3.0 服务标为实验实现；Mac 真实权限和输入也仍待实机验证。

2026-10-13；范围为新建 DeskBridge 管理层与固定 Deskflow 1.27.0 核心集成。这不是对整个上游仓库的完整安全审计。

## 已实现并核验

- 没有新增 HTTP、登录或云接口。自动发现采用 mDNS，仅接受格式受限的设备元数据和 RFC1918 地址；拒绝公网、链路本地 metadata、URL 和控制字符。浏览缓存限制 32 台、每条属性总量 1 KiB，每次最多刷新 4 条。
- 发现结果只提供端点线索，不能创建信任。接收端以已配对完整指纹和电脑名查找共享端；实际核心仍双向验证证书指纹。网络声明的同名/同指纹不能取代证书私钥证明。
- 0.2.1 的系统电脑名备用寻址仅针对已配对设备，名称使用既有白名单；全部解析结果必须是 RFC1918 IPv4，拒绝环回、公网和链路本地。解析值作为明确地址交给核心，不让核心再次按名称解析。DNS 结果不能修改指纹白名单；连接验证始终开启。后台解析线程仅一个，请求表最多 8 项，缓存 10 秒，调用方等待有截止时间；OS DNS 阻塞仍可能影响备用寻址可用性，但不会阻塞界面或无限创建线程。
- mDNS 发现事件仅排队有界服务名，解析转移到工作线程；首次短超时后会重试。每批最多 4 项，主动查询最多 8 个已配对目标；名称、角色或指纹冲突会明确提示。诊断仅显示错误类型/系统错误码，不输出异常原始数据、私钥或输入内容。
- 按用户的 DHCP 自动适配要求，共享端自动模式监听本机接口；接收端由系统选择出口网卡，不绑定回环。应按实际网络限制防火墙到允许的局域网。发现仅在私有网卡发布，不发布私钥或输入内容。
- 核心设置固定 `tlsEnabled=true` 和 `checkPeerFingerprints=true`；两端使用独立 SHA-256 白名单。不自动接受首次连接或网络返回的证书。真实回环测试验证未知证书拒绝、白名单证书允许、清空应用内白名单后拒绝。
- Windows 固定使用 portable 核心；实际白名单错误日志包含应用配置目录，验证其未使用 ProgramData 全局信任库。
- 设备名称、端口、地址、位置、指纹和配置字段受限。生成的电脑名称不能逃逸 INI/链接配置。外部程序使用参数数组；禁用进入/离开屏幕的命令执行选项。
- 每台电脑生成 RSA-3072 私钥和有效期一年的证书；证书与私钥相互匹配、时间有效性经启动检查。源文件、报告、安装包中不包含运行身份或私钥。
- POSIX 目录 0700 / 文件 0600。Windows 为独立配置目录和已有身份文件重设受保护 DACL，只授予当前用户及 SYSTEM，清除其他显式授权。测试先为临时身份赋予 Everyone 读取权限，再确认重新打开配置后该权限已移除。
- 拒绝 profile 路径与核心配置文件中的符号链接/目录联接。私有目录限制其他账号修改，原子写入使用目录内安全临时文件。相同 OS 账号恶意代码不属于本应用隔离边界。
- 最大 8 台设备，配置文件 64 KiB；剪贴板默认关闭，启用时设 1 MiB 上限。日志行截断到 4096 字符，最多 256 条待处理、300 行 UI 文本；生命周期事件独立保留且合并固定状态，日志不能挤掉停止/就绪事件。
- profile 使用 OS 文件锁防止并行配置修改；共享运行时禁用表单、布局及信任修改。探测超时 5 秒，停止超时后只终止自己创建的子进程。
- Windows 使用 kill-on-close Job Object 约束本应用子核心；常规停止先核对 named pipe 服务端 PID 为自身子核心，再发停止命令，失败时采用有界终止。不会向其他 Deskflow 实例发送停止指令。
- 打包控制器与原生核心运行库物理隔离，启动子进程时暂时清除冻结程序的 DLL 搜索目录并恢复父进程状态，过滤包内路径环境；未降低 TLS 验证。系统加载失败返回退出码，避免错误弹窗导致超时。
- 官方 Windows ZIP SHA-256 已核对；依赖采用官方来源固定版本/二进制 wheel，保留版本锁与构建日志。Deskflow 1.27.0 官方发行说明列出先前公开内存与 IPC 安全问题的修复；这不等于没有其他漏洞。
- 新增 zeroconf 固定为 0.151.5，已核对官方 2026-05 公告中解析与资源耗尽问题的修复版本（0.149.5–0.149.16），当前锁定版本高于这些修复版本；不代表全量依赖无漏洞。[官方公告列表](https://github.com/python-zeroconf/python-zeroconf/security/advisories)

## 需人工安全评审 / 仍待实机验证

1. **指纹与设备名未强制绑定。** 核心验证 trusted-clients 指纹集合后另行检查上报名称是否在布局中，不能证明某个证书只能声明某个名称。MVP 明确限定所有配对设备属于同一所有者、同一信任域，不能作为多用户或多租户权限边界。
2. **上游本地 IPC。** Deskflow 1.27.0 `src/lib/deskflow/ipc/IpcServer.cpp:34` 配置 WorldAccessOption，CoreIpcServer 的 stop 命令没有身份握手门禁。本管理层发送前核对 PID，只解决误停其他实例；没有改变其他本机用户能访问该上游端点的风险。当前核心不以 root / SYSTEM 运行；多用户主机或公开发布前应修补核心 IPC 的用户访问权限及身份验证，并完成兼容性测试。
3. **原生输入与解析器。** 复用核心的输入释放、报文解析、TLS 握手资源限制、clipboard 反序列化与并发未做全仓安全扫描。强制配对限制访问，但自动接口监听须由部署环境控制入站网络，不能把配置测试称作这些运行路径的全面验证。
4. **平台生命周期。** Windows 的 normal stop 与进程约束已实现；macOS / Ubuntu 的父进程突然崩溃、休眠恢复、Wayland 权限撤销和按键释放需实机验证。正常关闭界面会停止核心；首版没有实现其他平台的父进程死亡 watchdog。
5. **授权权限与秘密存储。** macOS/Wayland 系统授权必须授予实际输入核心。自签名证书以 pinning 作为信任锚，上游不等同公共 CA/主机名 PKI；对端证书过期的上游行为、撤销轮换与 OS Keychain/Credential Manager 存储须后续验证。
6. **发现服务可用性。** mDNS 和系统电脑名解析本身未认证；局域网攻击者可以伪造寻址线索或阻断组播，造成连接失败。TLS pinning 阻止由寻址直接授信，但不能保证抗发现 DoS。跨网段使用系统电脑名需已有 DNS 与 TCP 网络可达性；完全隔离网络仍须人工网络配置与评审。系统解析缓存和多个同名记录可能影响 DHCP 切换时效。

安全自查结论：本次管理层发现的日志生命周期丢失和显式文件权限残留已修复并回归；上游 IPC、身份名称绑定和跨平台原生输入边界标注需人工安全评审。
